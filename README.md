# Eisenhower Board

เว็บแอปจัดการงานส่วนตัวที่โฮสต์ได้เอง สร้างบนหลักการ Eisenhower Matrix — กรอบการตัดสินใจที่แบ่งงานตามความเร่งด่วนและความสำคัญ เหมาะสำหรับผู้ที่ต้องการควบคุมข้อมูลของตนเองโดยไม่พึ่งบริการคลาวด์ภายนอก

---

## ภาพรวม

แอปจะแบ่งทุกงานออกเป็น 4 ช่อง ดังนี้

| ช่อง | ชื่อ | แนวทางการรับมือ |
|---|---|---|
| เร่งด่วน + สำคัญ | ทำทันที | ลงมือทำเลย |
| ไม่เร่งด่วน + สำคัญ | วางแผนทำ | กำหนดเวลาและทำให้เสร็จ |
| เร่งด่วน + ไม่สำคัญ | มอบหมาย | ส่งต่อให้คนอื่น |
| ไม่เร่งด่วน + ไม่สำคัญ | ทำทีหลัง | ตัดทิ้งหรือเลื่อนออกไป |

## คุณสมบัติ

### หลัก

- บอร์ด Eisenhower Matrix 4 ช่อง ลากวางเพื่อย้ายช่องและจัดลำดับได้ทั้งด้วยเมาส์และการลากด้วยนิ้ว หรือโฟกัสที่ปุ่มจับแล้วใช้ลูกศร (ซ้าย/ขวา = เปลี่ยนช่อง, ขึ้น/ลง = จัดลำดับ)
- แผงบันทึกด่วนสำหรับจดความคิดก่อนจัดหมวดหมู่ และแปลงบันทึกเป็นงานได้ในคลิกเดียว
- กำหนดวันที่สิ้นสุด — เก็บเป็น UTC และแสดงตามเวลาท้องถิ่น หากไม่ระบุเวลาจะถือว่าครบกำหนดตอนสิ้นสุดวันนั้น
- ระบุเวลาในกำหนดส่งได้ ทำให้การแจ้งเตือนล่วงหน้าตรงกับเวลาจริง
- งานประจำแบบ ทุกวัน / ทุกสัปดาห์ / ทุกเดือน / ทุกปี — เมื่อทำเครื่องหมายว่าเสร็จ ระบบจะสร้างงานรอบถัดไปให้เอง
- แท็กและงานย่อย (checklist) ในแต่ละงาน พร้อมแถบความคืบหน้าบนการ์ด
- ตัวกรองงานตามสถานะ กำหนดส่ง และแท็ก — จำค่าที่เลือกไว้ในเครื่อง
- ธีมสว่างและมืด พร้อมตรวจจับค่าที่ตั้งไว้ในระบบปฏิบัติการโดยอัตโนมัติ

### สถิติ

- กราฟงานที่ปิดได้รายวันย้อนหลัง 14 วัน พร้อมยอดรวม 7 และ 30 วัน
- งานคงค้างแยกตามช่อง Q1–Q4 เพื่อดูว่ากำลังวิ่งตามงานด่วนหรืองานสำคัญ
- ค่าใช้จ่าย Subscription ต่อเดือนแยกตามกลุ่ม และรายการที่ครบกำหนดจ่ายใน 30 วันข้างหน้า

### Subscription

- เก็บราคาเป็นตัวเลขพร้อมสกุลเงินและรอบบิล (ต่อสัปดาห์ / เดือน / ไตรมาส / ปี / จ่ายครั้งเดียว)
- สรุปยอดรวมต่อเดือนและต่อปีอัตโนมัติ โดยเทียบทุกรอบบิลให้เป็นหน่วยเดียวกัน
- รวมยอดแยกตามสกุลเงิน ไม่มีการแปลงค่าเงินให้เอง และไม่นับรายการจ่ายครั้งเดียวเป็นค่าใช้จ่ายประจำ
- จัดกลุ่มรายการตามกลุ่มที่ตั้งเอง รอบบิล หรือสถานะ พร้อมยอดรวมของแต่ละกลุ่ม
- ปุ่มยืนยันการจ่ายที่เลื่อนวันต่ออายุไปรอบถัดไปให้อัตโนมัติ พร้อมเก็บประวัติการจ่ายไว้ดูย้อนหลัง
- รายการเดิมที่เคยกรอกราคาเป็นข้อความ เช่น `419 บาท/เดือน` จะถูกแปลงเป็นตัวเลขให้อัตโนมัติครั้งเดียวตอนอัปเกรด

### ข้อมูลของคุณ

- ส่งออกงาน บันทึก Subscription และการตั้งค่าทั้งหมดเป็นไฟล์ JSON ได้จากหน้าตั้งค่า
- นำไฟล์กลับเข้าระบบได้ 2 โหมด — เพิ่มต่อจากของเดิม หรือแทนที่ข้อมูลเดิมทั้งหมด
- ไฟล์ส่งออกไม่มี Telegram Bot Token และ Chat ID จึงต้องตั้งค่า Telegram ใหม่หลังกู้คืน
- สำรองอัตโนมัติวันละครั้งลงโฟลเดอร์ `data/backups` เก็บย้อนหลังตามจำนวนที่ตั้งไว้ (ปรับได้ด้วย `AUTO_BACKUP_ENABLED`, `AUTO_BACKUP_TIME`, `AUTO_BACKUP_KEEP`)

### ติดตั้งเป็นแอป (PWA)

- ติดตั้งลงหน้าจอโฮมได้ทั้งบนมือถือและเดสก์ท็อป
- Service worker แคชหน้าแอปไว้ จึงเปิดดูได้แม้เน็ตหลุด (ข้อมูลจาก API ยังต้องต่อเน็ต)
- ทางลัด "จดด่วน" จากไอคอนแอปเปิดหน้าต่างจดให้ทันที

### ความปลอดภัย

- เก็บ Session ใน SQLite และยกเลิก Session ทั้งหมดทันทีเมื่อเปลี่ยนรหัสผ่าน
- เข้ารหัส Telegram Bot Token ด้วย AES-256-GCM ก่อนบันทึกลงดิสก์
- Security headers, same-origin protection และ Rate limiting ที่ปรับค่าได้
- Setup token สำหรับป้องกันการยึดบัญชีระหว่างการตั้งค่าครั้งแรก

### Google Login

- เชื่อมต่อ Google Identity Services (OAuth 2.0) แบบเลือกเปิดใช้
- จำกัดสิทธิ์เข้าใช้งานเฉพาะอีเมล Google ที่อนุญาตไว้
- เชื่อมบัญชี Google กับบัญชีท้องถิ่นที่มีอยู่แล้วได้จากหน้าตั้งค่า

### การแจ้งเตือน

- ส่งสรุปงานประจำวันผ่าน Telegram Bot
- Scheduler มีระบบ claim-lock ป้องกันการส่งซ้ำเมื่อมีหลาย instance รันพร้อมกัน

### ความเสถียร

- Integration test อัตโนมัติด้วย Node.js built-in test runner
- CI pipeline ผ่าน GitHub Actions และอัปเดต Dependency อัตโนมัติด้วย Dependabot
- Docker health check ที่ endpoint `/api/health`

### ส่วนติดต่อผู้ใช้

- ดีไซน์แบบ flat/minimal พร้อมธีมสีให้เลือก 8 แบบ
- ฟอนต์ IBM Plex (OFL) โฮสต์ไว้ในโปรเจกต์เอง — ไม่เรียก Google Fonts ตอนใช้งาน จึงไม่รั่ว IP ผู้ใช้และใช้ได้ตอนออฟไลน์
- รองรับทุกขนาดหน้าจอ — desktop, tablet และ mobile
- รองรับการใช้งานด้วยแป้นพิมพ์อย่างครบถ้วน

## เทคโนโลยีที่ใช้

| ชั้น | เทคโนโลยี |
|---|---|
| Runtime | Node.js >= 20 |
| Framework | Express |
| ฐานข้อมูล | SQLite ผ่าน `better-sqlite3` |
| Frontend | HTML / CSS / JavaScript แบบ plain — ไม่ต้อง build |
| Container | Docker / Docker Compose |

## โครงสร้างโปรเจกต์

```
eisenhower-board/
├── src/              # โมดูลฝั่งเซิร์ฟเวอร์ (routes, auth, scheduler และอื่น ๆ)
├── public/           # ไฟล์ static frontend (HTML, CSS, JavaScript, ฟอนต์, manifest, service worker)
├── test/             # Integration tests
├── data/             # ฐานข้อมูล SQLite และไฟล์สำรองใน data/backups (สร้างตอน runtime, mount เป็น volume ใน Docker)
├── server.js         # จุดเริ่มต้นของแอปพลิเคชัน
├── Dockerfile
├── docker-compose.yml
└── .env.example      # ตัวอย่าง environment variables
```
